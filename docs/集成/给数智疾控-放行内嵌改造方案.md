## 一、背景（30 秒读完）

我们计划把贵方工作台 `http://88.8.130.150:50001/hbcdcagent/workbench/deepseek`
用 iframe **内嵌**到湖北 PHES 的页面里（父页 `http://88.7.129.120:50001`）。

目前贵方服务返回的响应头是：

```
Content-Security-Policy: frame-ancestors 'none'
```

`frame-ancestors 'none'` 的含义是**禁止任何页面内嵌它，连同源页面也禁**。
浏览器会直接拒绝渲染 iframe，我方表现为 **iframe 白屏**，控制台报：

```
Framing 'http://88.8.130.150:50001/' violates the following Content Security
Policy directive: "frame-ancestors 'none'"
```

需要贵方在**响应头**上放行我方这一个父页来源。**只改响应头，不改业务代码。**

---

## 二、要改成什么（一句话）

把

```
Content-Security-Policy: frame-ancestors 'none'
```

改为

```
Content-Security-Policy: frame-ancestors 'self' http://88.7.129.120:50001
```

并**移除 `X-Frame-Options`**（若存在 `DENY` / `SAMEORIGIN`）。

`'self'` 保留贵方自身页面内嵌能力（如有）；`http://88.7.129.120:50001` 是唯一被额外放行的父页来源。

> **为什么用 CSP 而不是 X-Frame-Options？**
> `X-Frame-Options` **没有多域名白名单能力**（老的 `ALLOW-FROM` 已被主流浏览器废弃），
> 多来源授权只能用 CSP `frame-ancestors` 表达。两者同时存在时浏览器以 CSP 为准，
> 但仍建议一并去掉 XFO，避免不同浏览器行为不一致。

# ② 打一个不存在的路径，看 404 响应上还有没有 CSP

```

## 四、具体改法（按来源三选一）

### 4.1 头是 nginx 加的（最常见）

```nginx
location /hbcdcagent/ {
    # ...原有配置保持不变...

    # 只改这一行：'none' → 'self' + 父页来源
    add_header Content-Security-Policy "frame-ancestors 'self' http://88.7.129.120:50001" always;
}
```

**两个必须注意的点：**

**① `add_header` 是整条替换，不是追加。**
如果原来那条 CSP 里还有别的指令（`default-src` / `script-src` / `img-src` / `connect-src` …），
必须**把它们一起写全**，否则等于把其余安全策略全部丢掉。例如原来是：

```
default-src 'self'; script-src 'self' 'unsafe-inline'; frame-ancestors 'none'
```

那就应该改成：

```
default-src 'self'; script-src 'self' 'unsafe-inline'; frame-ancestors 'self' http://88.7.129.120:50001
```

**② `add_header` 有继承阻断。**
同一个 `location` 内只要出现了**任何一条** `add_header`，父级（`http` / `server`）的 `add_header`
就会**全部失效**。如果该 location 里还配置了别的 `add_header`（`X-Content-Type-Options`、
`Strict-Transport-Security` 等），请把它们一起写进这个 location，或把 CSP 放到没有其他 `add_header`
的层级去，否则会顺带把其他安全头丢掉。

X-Frame-Options 如果也在 nginx：

```nginx
# 删除对应的 add_header。XFO 不支持白名单，保留 DENY 会让部分浏览器仍拒绝渲染
```

改完重载：

```bash
nginx -t && nginx -s reload
```

### 4.2 头是上游应用（Java / Spring Boot）加的

```java
// Spring Security 6
http.headers(h -> h
        .frameOptions(HeadersConfigurer.FrameOptionsConfig::disable)   // 关掉 X-Frame-Options
        .contentSecurityPolicy(c -> c.policyDirectives(
                "frame-ancestors 'self' http://88.7.129.120:50001")));
```

或自定义 Filter / 拦截器：

```java
resp.setHeader("Content-Security-Policy", "frame-ancestors 'self' http://88.7.129.120:50001");
```

> ⚠️ **如果应用前面还有 nginx，且 nginx 本身也加了 CSP，必须两边都改。**
> 两个同名响应头同时存在时，浏览器对 `frame-ancestors` 是**取交集**（更严），只改一边等于没改。
> 这种情况下 nginx 侧要先卸掉上游的头再自己加：
> ```nginx
> proxy_hide_header Content-Security-Policy;
> proxy_hide_header X-Frame-Options;
> add_header Content-Security-Policy "frame-ancestors 'self' http://88.7.129.120:50001" always;
> ```

### 4.3 头来自网关 / 统一安全基线（等保加固）

实测贵方响应里同时存在：

```
Content-Security-Policy: frame-ancestors 'none'
Cross-Origin-Resource-Policy: ...
Cross-Origin-Opener-Policy: ...
```

这一组三件套通常是**统一安全加固基线**统一下发的（不在业务代码里）。

这种情况不是改某处配置，而是**把路径加进白名单**：

- **变更内容**：`/hbcdcagent/**` 路径的 `frame-ancestors` 放行来源 `http://88.7.129.120:50001`
- **责任方**：安全 / 运维基线维护方（需走变更流程）
- **如需我方提供材料**：可以直接引用本文第二节的目标值

|---|---|---|
| `http://88.7.129.120:50001` | 湖北 PHES 生产环境 | ✅ 必需 |

`frame-ancestors` 的授权值必须精确到 `scheme://host:port`，**不支持域名通配**。
若后续我方还有其他环境要内嵌，会另行告知并更新本表。

> 且「父页 https + 子页 http」会被浏览器以**混合内容**为由拦截，这块需要双方一起定方案。
