# 工作台嵌入开发说明

父页面用 iframe 打开数智疾控工作台，并用 `ai:ask` 把问题送进去。协议文件是同目录的 `iframe-bridge.js`，可运行的父页面是 `嵌入示例.html`。

不要用 `file://` 打开父页面。`postMessage` 需要真实来源（协议、主机、端口）。

## 1. 让工作台允许被嵌

工作台默认 `frame-ancestors 'none'`，父页面会看到白屏。把父页面来源配进 BFF 的 `HBCDCAGENT_BFF_FRAME_ANCESTORS`，多个来源用逗号分隔，然后重启 BFF。

来源必须是完整的 `协议://主机:端口`，例如 `http://127.0.0.1:8765`。不要用 `*`，也不要少写端口。改响应头的核对方法见 [给数智疾控-放行内嵌改造方案.md](./给数智疾控-放行内嵌改造方案.md)。

## 2. 选一种打开方式

iframe 的地址都是工作台路径。生产环境在上面带一次性票据 `clientId` 和 `verifyData`。

| 方式 | 地址 | 打开后看到 |
| --- | --- | --- |
| 工作台 | `/hbcdcagent/workbench/deepseek?clientId=…&verifyData=…` | 侧栏和首页。收到问题后收起侧栏，进入这次会话 |
| 对话框 | 同一地址加上 `embed=chat` | 直接是对话框，没有侧栏、首页和右侧结果栏 |

两种都收 `ai:ask`。票据验票后会去掉 `clientId` 和 `verifyData`，其余参数保留，所以 `embed=chat` 可以和票据写在一起。

内嵌时页面自己验票，不要依赖顶层打开那次跳转。直接在浏览器地址栏打开同一链接会验票并进入工作台，这和 iframe 不是同一条路径。

## 3. 父页面怎么接

把 `iframe-bridge.js` 用 `<script>` 引进父页面，不要用 `import`。子页面来源用 `ScIframeBridge.resolveOrigin(iframe.src)` 算出来，放进 `allowedOrigins`。出站不会使用 `*`。

```html
<iframe id="frame" title="数智疾控工作台"></iframe>
<script src="./iframe-bridge.js"></script>
<script>
  var frame = document.getElementById('frame');
  var src = 'https://工作台主机/hbcdcagent/workbench/deepseek?clientId=…&verifyData=…&embed=chat';
  var origin = ScIframeBridge.resolveOrigin(src);
  var bridge = ScIframeBridge.host({ allowedOrigins: [origin] });
  bridge.on(function (msg) {
    if (msg.type === 'ai:done') {
      // payload.sessionId 是这一轮所在会话
    }
  });
  frame.src = src;
  frame.onload = function () {
    bridge.attach(frame.contentWindow, origin);
  };
  bridge.onReady(function () {
    bridge.emit('ai:ask', {
      content: '请概述近期需要关注的监测信号。',
      provideData: { area: '示例地区', range: '近7天' },
      msgId: '一次提问一个编号'
    }, 8000);
  });
</script>
```

握手完成前调用 `emit` 会排队，默认最多等 6 秒。页面加载较慢时，放在 `onReady` 里发更稳妥。等回执默认 4 秒，第三次参数可以加长，示例用的是 8000 毫秒。回执表示已受理，不是回答已经写完。

## 4. 问题字段

`ai:ask` 的载荷：

- `content`：必填。用户能看见的那句话，工作台立刻当成用户消息发出，并显示在对话里。不要只填进输入框等人再点发送。
- `provideData`：选填，字符串、对象或数组。只给模型，不出现在对话里。适合筛选范围、选中记录、一小段表格文本。
- `msgId`：选填。同一编号再发一次，工作台回已有会话，不会再开一轮。iframe 重载或连点时带上它。

受理回执：

- 成功：`{ accepted: true, sessionId, mode: 'new' }`。`sessionId` 是网关会话编号。
- 拒绝：`{ accepted: false, reason }`。常见原因是缺少 `content`，或会话没有建成。

回答从生成中变为结束时，工作台反向发送 `ai:done`，载荷是 `{ sessionId }`。父页面用它收起「分析中」。

`content` 和 `provideData` 加在一起的字符数默认不超过约 800 万。更大的表不要塞进这条消息，让工作台自己按需查询。

## 5. 用户身份

生产环境的身份来自票据里的用户。账号在 `HBCDCAGENT_BFF_OPS_USER_IDS` 里才是管理员，否则是普通用户。

本机没有票据时，`嵌入示例.html` 会先走 `/hbcdcagent/auth/mock?user=chenmin`，再打开工作台或对话框。陈敏是普通用户。这个模拟登录只在本机开启，接到会签发票据的环境后不要再走它。

父页面和工台不同源、且工台是纯 HTTP 时，浏览器不会保存会话 Cookie。内嵌页面会把验票返回的 `sessionId` 放在内存里继续用。

## 6. 本机看一遍

1. BFF 的 `HBCDCAGENT_BFF_FRAME_ANCESTORS` 包含 `http://127.0.0.1:8765`。
2. 在 `docs/集成` 目录执行 `python3 -m http.server 8765 --bind 127.0.0.1`。
3. 打开 `http://127.0.0.1:8765/嵌入示例.html`。默认是对话框，地址已写成 `http://127.0.0.1:50002/hbcdcagent/workbench/deepseek`。
4. 点「打开并提问」。握手完成后，输入框里的问题会自动送出。日志里出现 `accepted: true` 即表示工作台已开始这一轮。

「再发一个问题」只用于追加，不是第一次打开所必需的。

## 7. 打不开时先看这几处

- 控制台出现 `frame-ancestors 'none'`：父页面来源没配上，或协议、主机、端口有一项不一致。
- 日志停在握手：父页面来源和 `allowedOrigins` 不一致，或用了 `file://`。
- `accepted: false`：看 `reason`。没有 `content` 时会拒绝。
- 票据打不开：`verifyData` 一次性，用过或过期后要重新签发，不要写进仓库。
