交付给智能预警（系统 A）· 接入包 V1.0

智算疾控跨域免登 · 接入参数与实现约定

A 用本包签发一次性票据并跳转；B 验票建会话。双方运行时不互调。
签发方：智算疾控（B） 接收方：智能预警（A） 日期：2026-09-20 依据：跨域免登集成方案 V1.0

0. 怎么用这份材料

  1. 把第 1 节的 clientId、联调密钥、keyVersion 配进 A 后端（仅服务端，禁止进前端与 Git）。
  2. A 实现内部接口 POST /api/sso/ticket（必须带 A 登录态），按第 3、4 节加密。
  3. A 前端拿到 {clientId, verifyData} 后，按第 2 节拼接 URL，整页跳转（首期不做 iframe）。
  4. 票据即取即用，不要缓存；失败时提示用户从预警重新进入。
发送前由智算疾控填写 生产域名、生产密钥不写在本文档。联调密钥仅用于联调，与生产必须不同。生产密钥走密码管家 / 加密包+电话口令，禁止 IM 明文。

2. 跳转 URL（A 前端拼这一条）

首期仅支持整页跳转。iframe 嵌入待双方确认后再开。

https://<B域名>/hbcdcagent/workbench/deepseek?clientId=CDSS-B-ZJJK-001&verifyData=<票据>
  • 无 deepseek 路径时，改用 /hbcdcagent/workbench，query 不变。
  • verifyData 已是 Base64URL，不要二次 URL 编码（若误用标准 Base64 含 +/=，则必须编码，联调首日对齐）。
  • 不要把票据放到 hash（#）里；必须走 query，B 前端才能拦截。
  • A 不需要调用 B 的验票接口。打开上面的 URL 即可，B 自己拦参数、验票、建会话、清洗地址栏。
// 跳转示例
const { clientId, verifyData } = await fetch('/api/sso/ticket', { credentials: 'include' }).then(r => r.json()).then(r => r.data);
window.location.href =
  `https://<B域名>/hbcdcagent/workbench/deepseek?clientId=${clientId}&verifyData=${verifyData}`;

4. verifyData 二进制结构

keyVersion(1 字节)  ‖  IV(12 字节随机)  ‖  AES-GCM 密文  ‖  Tag(16 字节)
        └──────────────── 整体做 Base64URL（无 padding） ────────────────┘
AAD = clientId 的 UTF-8 字节（必须传，与 B 验票一致）

A 后端示意（JDK 8+，无需第三方加密库）：

import javax.crypto.Cipher;
import javax.crypto.spec.GCMParameterSpec;
import javax.crypto.spec.SecretKeySpec;
import java.nio.ByteBuffer;
import java.security.SecureRandom;
import java.util.Base64;

public final class SsoCipherUtil {
    private static final int IV_LEN = 12;
    private static final int TAG_BITS = 128;
    private static final SecureRandom RANDOM = new SecureRandom();

    /** payload = UTF-8 JSON；aad = clientId.getBytes("UTF-8") */
    public static String encrypt(byte[] keyBytes, int keyVersion, String payload, byte[] aad) {
        try {
            byte[] iv = new byte[IV_LEN];
            RANDOM.nextBytes(iv);
            Cipher cipher = Cipher.getInstance("AES/GCM/NoPadding");
            cipher.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(keyBytes, "AES"),
                    new GCMParameterSpec(TAG_BITS, iv));
            if (aad != null) cipher.updateAAD(aad);
            byte[] cipherText = cipher.doFinal(payload.getBytes("UTF-8")); // 含 Tag
            ByteBuffer buf = ByteBuffer.allocate(1 + IV_LEN + cipherText.length);
            buf.put((byte) keyVersion).put(iv).put(cipherText);
            return Base64.getUrlEncoder().withoutPadding().encodeToString(buf.array());
        } catch (Exception e) {
            throw new IllegalStateException("SSO encrypt failed", e);
        }
    }
}

// 密钥：标准 Base64 解码得到 32 字节
byte[] keyBytes = Base64.getDecoder().decode("luueY71IMszzt4bL8PocbEvkk1hXVpkY8Rpt2RxggUw=");
String verifyData = SsoCipherUtil.encrypt(
        keyBytes, 1, json, "CDSS-B-ZJJK-001".getBytes("UTF-8"));

5. A 会看到的结果（无需对接 B 错误码接口）

验票在 B 浏览器内完成。成功：进入工作台，地址栏去掉 clientId / verifyData。失败时 B 展示下列文案，并提供返回预警的链接（A 请把预警首页地址回传给 B）。

码原因用户提示
40001clientId 未登记或停用接入未授权，请联系管理员
40002超过 5 分钟，或时钟差过大链接已过期，请从智能预警系统重新进入
40003密文被改 / 密钥或 AAD 不一致凭证无效，请从智能预警系统重新进入
40004同一票据用第二次（含刷新）链接已失效，请重新进入
40005格式非法参数错误
40006验票被限流操作过于频繁，请稍后再试
刷新 票据一次性。用户在跳转后刷新，只要 B 会话还在就会直接进入，不应再带旧 verifyData。请不要把带票据的 URL 做成可收藏链接。

8. 不在本包内的内容

  • B 的验票接口、解密、会话 Cookie、工作台 API —— A 不用对接。
  • 用户中心 verifyCode / SM4 —— 那是另一条登录，与本免登无关。
  • 生产 AES 密钥 —— 线下交付。
  • 登出联动、iframe、国密 SM4-GCM —— 二期。
