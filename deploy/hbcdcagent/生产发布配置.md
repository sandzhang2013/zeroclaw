# 数智疾控工作台 — 发布生产要配置的内容

浏览器只访问 BFF。daemon 只监听本机 `127.0.0.1:42617`。不要把密钥写进 git。

两套启动方式共用同一份 `config.toml` 和同一个 `trusted_proxy_secret`：

```bash
# 模拟用户，不接用户中心、不验预警票据
./deploy/hbcdcagent/scripts/start-local.sh

# 用户中心 + 预警票据。需要 .env
./deploy/hbcdcagent/scripts/start-user-center.sh
```

源码目录会用 `target/debug/` 和 `web/dist/`。交付包会用包内 `bin/` 和 `web/dist/`。`.env` 放在 `deploy/hbcdcagent/.env`（源码机）或交付包的 `config/.env`。从 `env.example` 复制后再填。工作台操作（含技能与 `SKILL.md`）见 [工作台操作说明.md](./工作台操作说明.md)。

systemd 长期运行时，不要用上面的脚本占着终端。按下面第 2、3 节写 unit，先重启 daemon，再重启 BFF。

## 1. 两边必须相同的密钥

自己生成一串，不要用用户中心密钥，也不要用票据密钥：

```bash
openssl rand -hex 32
```

| 位置 | 变量或配置 |
| --- | --- |
| daemon | `ZEROCLAW_gateway__trusted_proxy_secret` |
| BFF | 同一个 `ZEROCLAW_gateway__trusted_proxy_secret` |

daemon 没配这项时，页面能开，`/api` 与 WebSocket 返回 `trusted_proxy_secret is not configured`。两边不一致时，返回 `Unauthorized — provide X-Auth-Secret`。

## 2. daemon

环境变量（`deploy/hbcdcagent/systemd/zeroclaw-secret.conf`）和 `~/.zeroclaw/config.toml` 都要满足：

| 项 | 生产值 | 作用 |
| --- | --- | --- |
| `gateway.trusted_proxy` | `true` | 接受 BFF 注入的身份 |
| `gateway.trusted_proxy_secret` | 与 BFF 相同 | 校验 `X-Auth-Secret` |
| `gateway.require_pairing` | `false` | 工作台不走设备配对。仍为 true 时接口返回 `pair first` |
| `gateway.path_prefix` | `/hbcdcagent` | 页面、接口、WebSocket 都在这个前缀下 |
| `gateway.web_dist_dir` | `/opt/zeroclaw/web/dist` | 交付的前端。源码机是仓库里的 `web/dist` |
| `gateway.host` / `port` | `127.0.0.1` / `42617` | 不对公网监听 |
| `[web_search] enabled` | `false` | 内网不能访问公网搜索 |
| `[http_request] enabled` | `false` | 不把任意 HTTP 放进工具列表 |

`config.toml` 里还要填写内网模型地址和实际使用的 agent 别名。模板是 `deploy/hbcdcagent/config.toml.template`。搜索和 HTTP 在模板里已经关闭。

工作台上看起来相近的几项来自两段配置，不要合成一项。agent 通过 `runtime_profile = "default"` 使用下面的运行配置。改的是运行 daemon 的那个用户的 `~/.zeroclaw/config.toml`，改完只重启 daemon。

| 配置 | 位置 | 上线值 | 不写时 | 作用 |
| --- | --- | --- | --- | --- |
| `context_window` | `[providers.models.<族>.<别名>]`，和 `model`、`uri` 同一段 | `128000` | 栏上没有模型窗口 | 对话栏分母。`28k/128k 22%` 里的 128k 是它，分子是上一轮实际送进模型的输入 |
| `max_context_tokens` | `[runtime_profiles.default]` | `128000` | **32000** | 对话堆到这个估算量就丢掉更早的轮次。提示里的 `configured token budget` 是这次实际用的数 |
| `max_tool_iterations` | `[runtime_profiles.default]` | `40` | **10**（写 `0` 也是 10） | 一轮里「模型提出工具调用并执行完」的次数上限，到上限这一轮停止 |
| `max_actions_per_hour` | `[runtime_profiles.default]` | `100` | **20** | 每个会话每小时最多执行这么多次工具动作。不写时是 20，模型会在提示里看到这个上限，并说「已达到速率限制（20次/小时）」后停下来。写 `0` 会禁掉全部动作。旧的 `[autonomy]` 同名字段不起这个作用 |

`context_window` 是模型能装下的窗口，`max_context_tokens` 是主动裁历史的预算。窗口写成 128000、预算没写时，栏上仍是 128k，但大约 3.2 万就会裁，裁完可能只显示百分之二十多。两项都要写上 128000，裁剪线才和窗口一致。

工具授权是 `[risk_profiles.default]`，agent 上要有 `risk_profile = "default"`。工作台选「自主」也不能高于这里的 `level`。`level` 不写时是 **supervised**：只读工具直接执行，其余工具弹出「需要授权工具调用」，倒计时约 120 秒，超时按拒绝。`always_ask` 不写时是空列表；写成工具名或 `"*"` 时，即使 `level = "full"` 也会弹授权。

上线在已有的 `allowed_commands`、`excluded_tools` 旁边补上这两行，不要用别的机器的整份 `config.toml` 覆盖：

```toml
[risk_profiles.default]
level = "full"
always_ask = []
allowed_commands = ["python3", "Rscript"]
excluded_tools = ["web_search", "web_fetch"]
```

`allowed_commands` 和 `excluded_tools` 按现场已有的列表保留。这样自主模式下不再为每次工具调用弹授权卡。

改完执行：

```bash
systemctl --user daemon-reload
systemctl --user restart zeroclaw
curl -sS http://127.0.0.1:42617/hbcdcagent/api/status
```

没有身份头时，这行应返回 `Unauthorized — provide X-Auth-Secret from the platform BFF`。若仍是 `trusted_proxy_secret is not configured` 或 `pair first`，daemon 没有读到上面的环境变量，需要重启的是正在监听 42617 的那个进程。

## 3. BFF

写入 `.env` 或 `hbcdcagent-bff.service`。`HBCDCAGENT_BFF_LOCAL_MOCK` 在生产必须是 `false`。

| 变量 | 生产要求 |
| --- | --- |
| `ZEROCLAW_gateway__trusted_proxy_secret` | 与 daemon 相同 |
| `HBCDCAGENT_BFF_UPSTREAM` | `http://127.0.0.1:42617` |
| `HBCDCAGENT_BFF_LISTEN` | BFF 绑定地址。交付默认 `0.0.0.0:50002`。浏览器若访问 `:50001`，要么 BFF 听 50001，要么前面的代理把 50001 转到 50002 |
| `HBCDCAGENT_BFF_PUBLIC_ORIGIN` | 浏览器地址栏里的源，含协议和端口，例如 `http://88.8.130.150:50001`。不要写成 daemon 端口 |
| `HBCDCAGENT_BFF_COOKIE_SECURE` | 站点是 HTTPS 时设 `true`：`hbcdcagent_session` 变成 `SameSite=None; Secure`，跨站 iframe 可以带上。站点是 HTTP 时必须 `false`，设成 `true` 浏览器会丢掉这张 Cookie |
| `HBCDCAGENT_BFF_OPS_USER_IDS` | 管理员账号，逗号分隔。票据里的 `userId` 在这里面才是管理员，否则是普通用户 |
| `HBCDCAGENT_SSO_CLIENT_ID` | 预警票据的 `clientId`，例如 `CDSS-B-ZJJK-001` |
| `HBCDCAGENT_SSO_KEY_B64` | 32 字节密钥的标准 Base64。与 `clientId` 必须同时填写 |
| `HBCDCAGENT_SSO_KEY_VERSION` | 默认 `1`，须与票据第一个字节一致 |
| `HBCDCAGENT_BFF_FRAME_ANCESTORS` | 允许嵌入工作台的父页面 origin，逗号分隔。不要填 `*`。当前父页是 `http://88.7.129.120:50001` |
| `USER_CENTER_BASE_URL` | 用户中心 OpenAPI，例如 `http://88.7.129.9/openapi` |
| `USER_CENTER_APP_ID` / `APP_KEY` / `APP_SECRET` | 用户中心分配的应用凭证 |
| `USER_CENTER_SIGN_TYPE` | `MD5` |
| `USER_CENTER_LOGIN_URL` / `CLIENT_ID` / `REALM` | 只有从工作台自己跳登录页时才要。门户带回 `verifyCode` 可以不填 |
| `USER_CENTER_TERMINAL` | `Web` |

门户回跳地址登记为：

```text
{HBCDCAGENT_BFF_PUBLIC_ORIGIN}/hbcdcagent/auth/callback
```

预警系统打开的地址是：

```text
{HBCDCAGENT_BFF_PUBLIC_ORIGIN}/hbcdcagent/workbench/deepseek?clientId=...&verifyData=...
```

BFF 不重定向这第一次打开。页面带着原来的 `clientId` 和 `verifyData` 自己验票，成功后再从地址栏去掉这两个参数，其他参数保留。门户用 iframe 嵌入时，会话放在页面内存里，不能靠 `SameSite=Lax` 的 Cookie。`verifyData` 是一次性的，验票一次就失效。

用户中心换票和预警票据是两把钥匙。`USER_CENTER_APP_SECRET` 不能当作 `HBCDCAGENT_SSO_KEY_B64`，也不能当作 `trusted_proxy_secret`。

## 4. 前端

生产页面来自 `web/dist`，不是 Vite 开发服务。界面改动后要重新 `npm run build`，再把 `web/dist` 拷到 daemon 的 `web_dist_dir`。只重启进程不会更新旧的 `index-*.js`。

侧栏角标 `v0.6.x` 是打包时写进 JS 的 `web/WORKBENCH_VERSION`。生产和本机显示不同，先对这个文件，不要对 `git rev-list --count HEAD`。历史被截断时，同一提交的计数会变小，角标就对不上。提交时如何加一位，见 [BUILD.md](./BUILD.md) 的「工作台角标版本」。

普通 HTTP 上选文件不再调用 `crypto.randomUUID`。旧包在 `http://88.8.130.150` 上选文件会报 `crypto.randomUUID is not a function`。

内嵌到门户 iframe 时，工作台按打开那一刻的浏览器缩放抵消后续缩放。直接打开工作台不抵消，用户仍可自行放大。

## 5. 发布后检查

1. `curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:42617/hbcdcagent/health` 为 200。
2. `curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:50002/hbcdcagent/auth/health` 为 200（若 BFF 改听了别的端口，换成那个端口）。
3. BFF 日志出现 `alert ticket sso enabled`。出现 `disabled` 就是票据密钥没配上。
4. 用预警链接进工作台后，地址栏不再带 `verifyData`，`/hbcdcagent/api/status` 为 200，会话能连上。
5. 左下角名字来自票据的 `nickName`，没有则用 `userName`，再没有则用 `userId`。
